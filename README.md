# BloodLink — “The journey of a drop”

A cinematic, story-driven landing page for **BloodLink**, a fictional platform connecting
voluntary blood donors, hospitals and licensed blood banks across Tamil Nadu.

> **Prototype.** Every donor, hospital, blood bank, stock level, request and testimonial is
> synthetic, generated by a seeded script. There are no real phone numbers, no real patients,
> no medical integrations. Labelled throughout the UI.

---

## 1. Run it

```bash
npm install
npm run dev        # http://localhost:5173
npm run build      # static output in /dist
npm run preview    # preview the production build
```

Node 18+. No environment variables required.

**Deploy:** the build is a plain static site.

| Host | Setting |
| --- | --- |
| Vercel | Framework `Vite`, build `npm run build`, output `dist` |
| Netlify | Build `npm run build`, publish `dist` |
| Any static host | Upload `dist/` |

`vercel.json` and `netlify.toml` are included (cache headers for `/img/*`, SPA fallback).

## 2. Structure

```
bloodlink/
├─ raw/                     source photographs (pre-grade, git-ignorable)
├─ public/img/              generated AVIF + WebP renditions + blur-up placeholders
├─ scripts/
│  ├─ gen-data.mjs          seeded synthetic data generator  (npm run data)
│  └─ build-images.mjs      consistent grade → responsive renditions (npm run images)
├─ src/
│  ├─ assets/images.json    generated image manifest (srcset + LQIP)
│  ├─ data/                 MOCK JSON — imported by services only
│  ├─ services/api.js       the only data boundary  ← read this first
│  ├─ services/mockStore.js in-memory "database" (deleted in production)
│  ├─ hooks/                useLenis, useCountUp, useReducedMotion
│  ├─ components/           Nav, Picture, DonorForm, BloodCellField, …
│  │                        TamilNaduLeafletMap (live OSM) + TamilNaduMap (fallback)
│  ├─ sections/             one file per page section
│  └─ styles/index.css      design tokens, base type, reduced-motion overrides
```

**The architectural rule:** components and sections *never* import from `/src/data`.
They call `src/services/api.js` and render whatever JSON comes back. `api.js` is the seam.

## 3. Service → endpoint map

Every function already returns the shape a REST API would. To go live, replace the body of
`request()` inside `api.js` with `fetch()` — **no component changes**.

| Service function | Method & endpoint | Query / body | Returns |
| --- | --- | --- | --- |
| `getDonors({ group, district, availableOnly })` | `GET /api/donors` | `?blood_group=O%2B&district_slug=chennai&available_only=true` | `{ data: Donor[], meta: { total, filters, is_sample } }` |
| `getRequests({ district, group })` | `GET /api/requests` | `?district_slug=madurai&blood_group=B-` | `{ data: Request[], meta: { total, critical } }` |
| `getBanks({ district, group })` | `GET /api/banks` | `?district_slug=salem&blood_group=A%2B` | `{ data: BloodBank[] (with `stock_status`), meta }` |
| `getImpact()` | `GET /api/impact` | — | `{ data: { counters, monthly_donations, district_totals, stories }, meta }` |
| `getReference()` | `GET /api/reference` | — | `{ data: { blood_groups, districts } }` |
| `getDonor(id)` | `GET /api/donors/:id` | — | `{ data: Donor }` · 404 → `ApiError` |
| `registerDonor(payload)` | `POST /api/donors` | JSON body, `snake_case` | `{ data: Donor, meta: { message } }` · 422 → `ApiError` |
| `pledgeRequest(id)` | `POST /api/requests/:id/pledges` | — | `{ data: Request, meta: { remaining_units } }` · 409 → `ApiError` |
| `requestCamp(payload)` | `POST /api/camps` | JSON body | `{ data: { camp_request_id, status } }` |

Errors are uniform: `ApiError { message, status, code }` with codes
`validation_error`, `invalid_phone`, `not_found`, `already_fulfilled`, `internal_error`.

### Field names

All records use `snake_case` mapped straight to SQL columns, e.g.

```sql
donors(donor_id PK, first_name, last_initial, blood_group, district_slug,
       district_name, area, age_band, is_available, is_verified,
       last_donation_date, total_donations, response_minutes, distance_km,
       consent_share_contact, created_at)

requests(request_id PK, hospital_name, district_slug, blood_group,
         units_needed, units_pledged, urgency, needed_by, patient_context,
         verified_by, verified_at, contact_channel, status, created_at)

blood_banks(bank_id PK, name, district_slug, area, type, is_verified,
            cold_chain_ok, open_hours, component_separation, stock_units JSONB,
            total_units, last_updated)
```

`display_name` (first name + initial) and `stock_status` are **server-derived** fields —
the client never composes them, so private data can't leak by accident.

## 5. Why the animation choices

Each animation exists to carry a piece of the story — none is decorative.

1. **The drop falls, lands on the headline, ripples the photo open.** One crimson drop
   (always the same SVG path, reused site-wide) falls from the top, lands on the word
   *life*, and releases three expanding rings that wipe the hero photograph open via
   `clip-path: circle()`. It plays once per session (`sessionStorage`), so returning
   users get a composed page instead of an impatient one.

2. **Pinned “Donate → Test → Store → Deliver”.** A CSS `sticky` pin maps scroll progress
   (via ScrollTrigger) to four stages. The **blood bag fills as you scroll** — the fill is
   literally the scroll position, so the progress bar *is* the story. Only the active
   photograph is mounted; the outgoing one cross-fades. No blur filters are animated
   (they force full-width repaints on mid-range Android).

3. **The ECG quickens on Urgent Requests.** A thin dash-offset trace runs across the page
   top at ~1 beat / 5.4s. An IntersectionObserver on the urgent section raises the rate to
   ~2× with a physiological ease, so the page itself becomes anxious where the content is.

4. **Blood-group choice morphs the drop.** Selecting a chip re-labels the same drop glyph
   (AnimatePresence swap) and re-orders donor cards with a staggered layout transition —
   the interface behaves like a live query, because it is one.

5. **Pledging is quiet, not celebratory.** The unit bar animates, then a check-mark
   *draws itself* (`pathLength` 0→1) and the button resolves to “Thank you — coordinator
   will call”. No confetti: this is somebody's emergency.

6. **Impact numbers, then three silhouettes.** Counters use an eased count-up on first
   entry. “One donation reaches three lives” is shown literally — three figures light up in
   sequence, each filled from the bottom with its component's colour and shelf life.

7. **Magnetic buttons, tactile press.** Primary buttons drift ~12 px toward the cursor
   (label drifts further for mass) and compress to 0.97 on press. Disabled on touch.

8. **One easing curve everywhere:** `cubic-bezier(0.22, 1, 0.36, 1)` — tokens in
   `tailwind.config.js` (`ease-calm`) and a shared `EASE` constant.

**Reduced motion** (`prefers-reduced-motion: reduce`) is handled at three levels: the CSS
layer collapses durations, `usePrefersReducedMotion` swaps transforms for fades, the
canvas field renders one static frame, and the journey story falls back to a stacked,
non-pinned list.

## 6. The map

The Blood Bank Network section uses **Leaflet + OpenStreetMap tiles**, centred and bounded on
Tamil Nadu with eight district markers at real coordinates.

- **Markers** are `L.divIcon`s: teal = verified stock, crimson = donors only, with a soft
  pulse. Clicking a marker filters the directory beside it and the map flies to that district;
  clicking open water clears the filter.
- **Spotlight.** Everything outside the state boundary is veiled (`L.polygon` with a
  world-sized ring as a hole) and the boundary itself is a dashed crimson hairline — so the
  basemap answers *where* and the veil answers *which*.
- **Scrolling is never hijacked:** `scrollWheelZoom: false`, so Lenis keeps ownership of the
  page. Zoom is via the +/− control, pinch, or keyboard.
- **Theme.** Tiles are colour-graded to the site palette; dark mode drops a scrim pane over
  the basemap rather than inverting it (inverted OSM labels are unreadable, and `invert()`
  also painted a stray blue frame around the tile layer).
- **Progressive enhancement.** Leaflet (~153 kB, code-split and lazy) only *takes over* once a
  tile has genuinely painted. If tiles are blocked, offline, or slow past 6 s, the section
  keeps showing the vector outline diagram and says so: *"Tiles unreachable — showing
  outline"*. A **Live map / Outline** switch lets the reader pick either view.

### Map tiles before launch

The default is OSM's public tile service — acceptable for a prototype under their
[tile usage policy](https://operations.osmfoundation.org/policies/tiles/) (attribution kept,
no bulk downloading), but **not** for production traffic. Set your own before launch:

```bash
VITE_MAP_TILES_URL=https://your-tile-host/{z}/{x}/{y}.png
VITE_MAP_ATTRIBUTION=© Your Tile Provider
```

Nothing else needs to change. If you want to self-host, `protomaps` + PMTiles or a
`maplibre-gl` raster style are drop-in replacements for the `L.tileLayer` call.

## 7. Performance & accessibility

- **Images:** 5 responsive widths per photo, AVIF + WebP, 24px blur-up LQIP inlined,
  `loading="lazy"` + `decoding="async"` below the fold, `fetchpriority="high"` on the hero.
  Regenerate with `npm run images` after replacing any source file.
- **Motion budget:** the cell field is 14 sprites (cap 20) on one canvas, pre-rendered
  offscreen, paused by IntersectionObserver when off-screen, `devicePixelRatio` capped at 2.
- **JS:** Framer Motion, GSAP and React are split into separate chunks, and Leaflet is
  lazy-loaded only when the Network section is reached, so the hero never pays for the map.
- **Mobile-first** from 360px; no horizontal scroll at any width tested (390/820/1280/1440).
- **Focus:** `:focus-visible` rings on every control, a skip link, focus trap + Escape in
  the modal, `aria-expanded`, `aria-pressed`, `aria-checked`, `role="progressbar"` with
  values, `aria-live` on result counts and toasts, and a body scroll lock while the modal is open.
- **Contrast:** body copy uses ≥ 4.5:1 against the active surface in both themes
  (`.card` resets its own colour context so a card never inherits light-on-light).
- **States:** loading skeletons, empty states with a recovery action, and error states with
  retry exist for donors, requests, banks and impact.
- **Tamil:** `lang="ta"` blocks switch to Noto Sans Tamil with a taller line-height.

## 9. Known prototype limits

- No authentication, no persistence: a refresh resets pledges (state lives in `mockStore`).
- The Tamil Nadu outline (used for the map spotlight and the offline fallback) is a
  **stylised** shape, not a survey-accurate boundary. The live map's geography is real OSM
  data; only the veil's edge is approximate.
- The map is bounded to Tamil Nadu (`maxBounds`) so readers can't wander off — remove the
  bound if you extend the network to neighbouring states.
- “Request contact” and “Host a camp” open a local confirmation; nothing is transmitted.
- Lighthouse: the page is built to the mobile budget, but please re-measure on your host —
  font and image caching behave differently behind a CDN.
